# 方法论：受控取舍的角色渲染

[English](methodology_EN.md) · [项目首页](../README.md) · [验证框架](validation-framework.md)

本方法从[工程技术总结](../docs/TECHNICAL_SUMMARY.md)与[LookDev 工作流文档](../docs/WORKFLOW.md)抽象而来。它指导 Blender/Cycles 中的决策，不将某个工程节点或参数宣称为通用配方。

```text
Stylized Character Rendering
= Physical Spatial Coherence
+ Bounded Identity Protection
```

## 七步决策流程

1. **明确视觉不变量。** 写下该角色不可丢失的眼形、表情、面颊、鼻影、轮廓和核心颜色；同时指出证据来自原设计、当前工程或已观察的成片。
2. **明确物理自由度。** 为区域和材质分别决定哪些属性可随灯光、视角、姿态与环境改变。眼与表情可受强保护；头发、布料和金属需要更充分的真实响应。避免给整名角色一个统一比例。
3. **找到最早出错层。** 按几何/拓扑 → UV/源贴图 → 通道解码 → 法线/切线 → BSDF → 设计性 NPR → 灯光 → 相机/景深 → 可见性 → 合成/色彩管理排查。用单变量隔离，而不是同时调多个参数。
4. **做最小且有边界的修改。** 先针对造成问题的区域或属性修正，并设定影响范围。面颊可平滑、鼻与下巴应保留三维线索；不要 Uniform Face Flatten。若修正只改善一个角度却损害 3/4 或动画稳定性，就不应推广。
5. **重新耦合回环境。** `Decouple → Art Direction → Controlled Re-coupling`。被设计保护的脸仍需有限响应环境颜色、亮度、曝光与灯光；分别检查 chromatic adaptation 和 luminance adaptation，避免让脸像被另一套摄影棚灯照亮。
6. **故意测试最差条件。** 进行角度、光向、环境、曝光、姿态和时间采样；比较同条件下的消融版本。优先看最差帧是否仍像同一个角色、是否仍在同一个世界，而不是挑最好的一帧。
7. **保留对照、回滚与可复现性。** 记录输入、材质/灯光状态、修改理由、A/B 图和失效条件。保留已接受基准，危险修改使用副本与恢复路径，避免把历史实验误当当前有效状态。

## 后续方法扩展：Shading Responsibility Allocation

[Jinshi 后续案例](../docs/JINSHI_RESPONSIBILITY_CASE_STUDY.md)在原公式之外增加一条**操作性诊断轴**，不替换 `Physical Spatial Coherence + Bounded Identity Protection`：找到最早出错层后，还要问“这个视觉线索应由谁主要负责，物理世界可改变它多少？”

对鼻影、面颊、眼窝、环境染色和 rim 分离等线索，分别记录**主要责任系统**、允许的物理自由度、必须保护的身份范围，以及可参与但不应主导的次要系统。几何负责轮廓，局部法线抑制不需要的几何响应，设计性脸影控制身份关键边界，PBR 提供材质与空间响应，灯光和环境帮助角色融入场景；具体分工仍需由当前资产和测试决定。

**Redundant Volume Encoding** 是多个系统强烈重复表达同一个鼻、眼窝或面颊体积线索的风险。各组件单独看可能合理，叠加后却可能过度塑造。先隔离责任层，单变量比较，再做最小修改；不要因“脸上出现问题”就默认重写面部材质。Jinshi 的数值只属于该案例提供的记录，不是通用参数。

## 证据纪律

区分五类陈述：**工程内事实**（数据块、节点、脚本、设置），**成片观察**（最终图像/动画可见现象），**公开技术资料支持**（一般技术先例），**方法论推断**（由案例提出、仍需跨案例验证的原则），**工作假说**（对商业渲染的画面推断）。Jinshi 的工程事件目前只有提供的案例笔记，未在本仓库独立复核。成片能支持整个组合在特定案例中的结果，不能单独证明某算法的唯一因果；公开画面也不能确认商业 Shader 的内部结构。

## 何时推广一个修正

先完成[验证框架](validation-framework.md)的受控测试，再比较身份保持、空间与 shading-domain 一致性、跨视角和时间稳定性、曝光鲁棒性与环境融合。记录最差样本及其失败机制。只有当修正改善这些条件且仍能回滚，才把它加入可复用工作流。
